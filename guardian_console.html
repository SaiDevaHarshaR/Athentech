What happens when you refresh a profile?

Only the selected client's cached schema mapping is refreshed. The underlying client SQL Server tables are not changed. If a check reports a missing field, open Playbooks before making any configuration changes.

Practical recovery

One problem. Clear steps.

Choose the issue you are facing. Each guide stays collapsed until you need it.

▦ Excel collection export+
  1. Verify whether the problem affects Today, Yesterday, or This Month.
  2. Open Diagnostics and run a client self-check.
  3. Review the collection metric and rejected mappings in schema diagnostics.
  4. Compare the exported figures with verified SQL Server values. Billed totals must not be presented as cash collected.
  5. If monthly only fails, send the support report to your technical contact.
Do not manually edit collection tables or overwrite another client's metric configuration.
⌁ SQL Server connection failed+
  1. Check whether other clients are responding normally.
  2. Run the affected client's self-check once the circuit breaker allows a retry.
  3. Ask the database administrator to verify server reachability and login permissions.
  4. Check for a recent host, firewall, password, or network change.
  5. Retry the same read-only report after connectivity is restored.
Never change client database credentials or permissions without authorization.
◇ AI Agent response failed+
  1. Try a known instant report to separate SQL/database errors from AI-provider errors.
  2. Check Guardian signals for rate limits, timeouts, or schema errors.
  3. Confirm the LLM provider credentials and quota in the secure server settings.
  4. If only one client is affected, run its self-check.
  5. Escalate with the sanitized report if errors persist.
□ PDF / Smart Report failed+
  1. Check whether a normal text report works for the same patient or UHID.
  2. Confirm the patient identity and required authenticated results exist.
  3. Check backend errors for template, renderer, or AI provider failures.
  4. Confirm sufficient storage and browser-renderer availability on the app server.
  5. Do not substitute another patient's data when a report cannot be generated.
◈ Admin panel or sign-in issue+
  1. Check whether the Guardian console page loads.
  2. If login reports HTML instead of JSON, check the IIS rewrite rule for /admin/guardian/*.
  3. Test the corresponding local FastAPI endpoint on the actual backend port.
  4. Check admin-account status and authentication logs.
  5. Avoid deleting or reseeding admin tables as a troubleshooting shortcut.
↗ Client schema changed+
  1. Run Diagnostics → Compare schema snapshot.
  2. View current schema diagnostics for missing columns and rejected pins.
  3. Refresh only the client's schema cache and recheck.
  4. Confirm any new column mapping with the LIS vendor or technical owner.
  5. Escalate if the table family itself has changed.
Schema refresh is not a database migration. It does not create or alter client tables.

1. What is Sahasra Guardian?

Guardian is a support workspace for the Sahasra AI Agent. It reports recent client-specific errors, offers plain-language troubleshooting, and checks whether a client database is reachable and its expected schema can be read. It does not replace the main Admin panel; the two serve different purposes.

2. First-time use

  1. Open the Guardian Console link on your deployed Sahasra website.
  2. Sign in using the same authorized admin account.
  3. The Overview page opens automatically; the sign-in form disappears.
  4. Review incidents. A temporarily paused client usually means repeated database failures triggered its circuit breaker.
  5. To investigate a client, choose Diagnostics at the top and enter its activation code.
  6. Start with Run self-check, then use the other tools only as needed.
  7. Use Playbooks for recovery steps, or export the support report if escalation is necessary.

3. What each button does

ButtonWhat happens
Refresh statusRequests the current Guardian status and recent incidents from the backend.
Run self-checkChecks one client's connection, available schema information, and configured mappings. It is intended to be read-only.
View schema diagnosticsDisplays what Guardian detected about the client's report capabilities and configuration.
Compare schema snapshotCompares the current client schema with the previously saved snapshot. Its snapshot metadata may be updated, but LIS tables are not supposed to be modified.
Refresh cached profileRebuilds the selected client's cached schema profile without editing its LIS data.
Download support reportDownloads a sanitized JSON diagnostic report to share with technical support.
Sign outClears the Guardian session token held in this browser page.

4. What to do when something fails

  1. Note the client, time, and action that failed.
  2. Open Diagnostics and perform a client self-check.
  3. Open Playbooks and follow the matching guide.
  4. If the error remains, click Download support report.
  5. Share it securely with your designated technical contact. Never send passwords or full patient data.

If the Guardian login itself fails, check whether IIS is rewriting /admin/guardian/* requests to FastAPI rather than serving a static 404 or HTML error page.

5. Limits and safety

  • Guardian can explain errors and run the supported checks. It cannot guarantee repair of a new code bug.
  • Do not treat automatic collection-column detection as proof of accounting meaning; distinguish billed amounts from received money.
  • Do not grant write access to client LIS databases just to make a report work.
  • Keep backups, known-good app releases, and a named technical escalation contact.
  • Not all incidents are detected immediately; status reflects what the deployed backend has recorded.
